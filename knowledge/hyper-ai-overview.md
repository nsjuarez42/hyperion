# HYPER-AI overview

Every sentence below is taken from the project deliverables (D3.3) and the project website and IDE tutorial pages in this folder. It groups the core facts so that general questions find them in one place.

## What is HYPER-AI?

HYPER-AI is an EU project. HYPER-AI is a hyper-distributed, self-managed system designed to enable intelligent orchestration of computing, storage, and communication resources across the cloud-edge-IoT continuum. HYPER-AI aims to redefine data processing with distributed computing swarms: autonomous networks of interconnected nodes that adapt and optimise resources across the cloud, edge, and IoT continuum.

## How does the HYPER-AI platform work?

The architecture defines how diverse computational assets, that range from cloud-based resources to constrained IoT devices, can be abstracted, registered, discovered, and dynamically orchestrated under a common control framework. Its design principles include computational abstraction, Kubernetes-native orchestration, distributed trust and security via Distributed Ledger Technology (DLT), and self-configuration, self-healing, self-optimization and self-protection (self-CHOP) autonomy.

## What are the main parts of the HYPER-AI architecture?

The architecture includes infrastructure-level abstraction, open connectors, and intelligent orchestration mechanisms for workload placement and optimization. It includes dedicated modules for swarm formation, federated learning, distributed resource optimization, and intrusion detection. It also incorporates a flexible administration and development environment.

## Which use cases (verticals) does HYPER-AI target?

The five vertical domains of the project are Manufacturing, Energy, Agriculture, Automotive, and Healthcare. The project website describes them as Mobility and Automotive, Industry 4.0, Healthcare, Green energy, and Farming and Agriculture.

## What is the HyperAI IDE?

The HyperAI IDE is the integrated development environment of the HYPER-AI project. It is used to build, run, and inspect AI workflows. Users describe workloads as application profiles, and the IDE checks these files against the native-app and device-app rules.
